# Qwen3.6 Testbed 3: measured replay implementation

## Scope

Add Qwen3.6-35B-A3B IQ1_M to the playground as Testbed 3. Retain the
existing Testbed 1/2 examples, prompts, output and playback behavior. Testbed 3
uses a MacBook Pro (M3 Pro, 18 GB unified memory) and a Windows desktop
(Core i9-9900K, RTX 2080 Ti GPU 0 with 11 GB VRAM, 64 GB RAM) on the same LAN.
Its names, specifications, illustrations, local-network description and
result-card labels must not inherit the existing remote-laptop/server setup.

The user explicitly requires DFlash **off and on**, not a synthetic speed
multiplier. Reuse the three Qwen3.8-27B prompt strings verbatim:

- `math`: residue classes modulo 12 and a concise proof;
- `cs`: merge closed intervals, complexity and two edge-case tests;
- `literature`: perspective and silence in the lone-sail/river quotation.

## Measurement contract

- Matrix: 3 prompts × Mac llama.cpp / Windows llama.cpp / two-host PRIMA
  × DFlash off / on = 18 complete traces.
- Keep the random seed 1234 and repeat penalty 1. The user's latest revision
  explicitly permits ordinary sampling rather than fixed temperature. Do not
  send `temperature`, `top_k`, `top_p`, or `min_p` in measured requests; record
  the server's effective settings, and reject accidental temperature 0 or
  top-k 1 restrictions. Use the same defaults across the comparison where
  possible and report any difference instead of hiding it. Omit `n_predict` from
  measured requests, verify the server's effective value is -1, and let output
  continue naturally to EOS. The earlier 1024-token runs are diagnostic only,
  not final website measurements. A transport timeout is a failed/incomplete
  capture, never a substitute for EOS. A bounded, excluded warmup is not a
  measured request.
- Use identical rendered prompt token IDs and model bytes across backends.
  Disable prompt caching, keep concurrency 1, and exclude declared warmup.
  No padding to the earlier 8K paper workload: these are the existing short
  playground prompts, not the previous performance fixture.
- Target the model-declared maximum context capacity, expected 262144; do
  not silently reduce context. Reserve full F16 KV and use Flash Attention.
- Use the clean official llama.cpp 9558fa44c baseline on each native platform.
  Prefer accelerator placement for non-expert/shared-expert weights. If the
  full model cannot fit, retain as many routed-expert layers on the GPU as
  reviewed memory permits and use supported CPU expert placement for the
  rest. File-backed mmap is not a claimed custom disk-streaming engine.
- Keep a device's target expert placement the same for DFlash off/on when
  possible; record any unavoidable difference rather than hide it.
- PRIMA uses its tested FP32-activation Mac/Windows two-host runtime, with
  the DFlash-on path explicitly using the appropriate reduced feature codec.
- Capture HTTP SSE arrival timestamps on each server's own host/loopback,
  with a monotonic clock. Do not time Windows through an SSH tunnel.
- TTFT is request submission to the first generated token event. TPOT is
  `(last_token_time - first_token_time) / (output_token_count - 1)`.
  The displayed throughput is `1 / request_mean_TPOT`, not server compute-only
  TG or a pooled ratio across different requests. Record EOS/counting policy.
- Preserve real token IDs, pieces and arrival groups. Tokens received in one
  atomic event share its observed timestamp; never invent internal timings.
  Retain raw SSE and request/configuration/provenance alongside exported data.

## Operational boundaries

Mac is the only authoring environment. Windows receives explicit reviewed
scripts/source and builds/runs natively. Never contact Linux/MBZUAI nodes;
never run `test_all`, use sub-agents, alter the Prima official gitlink/56-patch
inventory, or stop unrelated workloads. Check Mac memory and GPU0 inventory
before heavy runs. Bound every launch and cleanup to captured PIDs; keep
artifacts in the project or dedicated temporary/benchmark directories.

The codegraph service initially returned `Transport closed`. It later
recovered, and the website was indexed and queried for the replay review.
Targeted file inspection was used for excluded benchmark helpers and diffs.

## Capacity probes and current data gate

The user accepted the later PRIMA measurements and requested fresh standalone
llama.cpp baselines. Those twelve native retests are complete and replace the
earlier standalone records. PRIMA-on uses whole median-TPOT requests from the
declared repeat groups; PRIMA-off retains its three original EOS records.
The selection, candidate measurements and limitations are documented in
[`qwen36-testbed3.md`](../benchmarks/qwen36-testbed3.md) and its explicit capture
manifest. No historical long-prompt rate or synthetic acceleration multiplier
is substituted. Extended visibility/missing-data checks and the answer-quality
disclosure passed the final browser rerun.

Earlier PRIMA-on code runs near 20 tok/s coincided with low Mac GPU frequency;
later unchanged-runtime runs recovered to approximately 42–43 tok/s without
temporary power probes. Neither a permanent power fix nor network competition
has been established as the cause. The accepted data preserves that uncertainty.

- Mac: `--no-mmap -ngl all -ncmoe 24`, F16 KV, FA on, capacity 262144,
  batch/ubatch 8192/512, six CPU threads. Transformer non-expert/shared-expert weights
  remain on Metal; 24 routed-expert blocks compute on CPU. With mmap,
  Metal's mapped span still covered most of the model and startup failed.
  Separating the buffers worked. The 16-CPU-block probe exceeded Metal's
  working-set limit; it is a preserved failure, not a measurement. The
  successful 24-block DFlash-on diagnostic reached a 15.78 GiB OS-reported
  lifetime physical-footprint peak; the final retest reached 15.74 GiB.
  This is not additional RAM beyond UMA. Default input-embedding placement
  is retained, without an explicit GPU tensor override.
- Windows: native official CUDA build uses CUDA 12.4.1, MSVC 19.44, sm_75,
  CUDA Graphs enabled. Source is a checksummed export of official 9558fa44c,
  with no source modifications. No Git directory was transferred, so its
  executable version reports `commit unknown`; the official archive and
  binary hashes bind its provenance instead. An initially missing official
  UI provisioning script was supplied from the same commit; unused embedded
  UI/downloads and the desktop app were disabled with build options.
- Windows: `--no-mmap -ngl all -ncmoe 34`, F16 KV, FA on, capacity 262144,
  batch/ubatch 8192/512, eight CPU threads. The DFlash-on short probe peaked
  at 10523 MiB GPU0 usage with 505 MiB free. The target placement is held
  fixed between modes, not independently maximized for each mode. The final
  DFlash-on retest reached 10583 MiB with 445 MiB free. The physical Ethernet
  adapter reported 100 Mbps.
- Both model GGUF SHA-256 values were rechecked on both hosts. The natural-
  EOS capture scripts and three frozen requests also match across hosts.
- Nine earlier capped traces and subsequent unlimited greedy attempts are
  diagnostic only. Mathematics showed
  arithmetic mistakes in an official non-DFlash output, and repetition in
  DFlash outputs. Do not silently edit, replace, shorten, or claim that these
  answers are correct. The user approved restoring ordinary sampling with a
  fixed seed, and reiterated that no sub-agents may be used. Both old greedy
  model processes were stopped by captured PID or bounded timeout before the
  new sampling experiment.
- Final dataset export is fail-closed: all 18 requests must match the frozen
  prompt/sampling contract, have a natural EOS, no truncation or prompt-cache
  reuse, and recompute exactly from their captured SSE records. Different-
  context blog-only captures are rejected and remain outside this website
  dataset and its public documentation.
